## Why

The shipped board renders the conquest map as real, named European countries (Spain, France, UK,
Germany, Italy, Poland, Sweden, Ukraine), drawn with real-geography SVG paths baked from Natural
Earth data. Product direction has moved away from real-world geography entirely: the map should
read as "lands of different shapes, appropriately located according to game balance" — an abstract
territory board, not a small atlas of Europe, with zero real-world place names, so the game isn't
implicitly making claims about (or trivializing) real countries and borders. Separately, the
region count was cut from 16 to 8 by `mobile-optimization` purely to keep touch targets tappable on
phones; that trade-off no longer needs to hold now that the map has pinch-to-zoom
(`MapViewport.tsx`, already shipped), so this is also the right moment to restore the 18-territory
board CLAUDE.md describes as the intended shape of the game.

## What Changes

- **BREAKING**: Replace `Data/map.json`'s content — id, region count, names, geometry — with a
  fully abstract 18-region map (`id: "abstract-18"`). No in-flight game or persisted state survives
  this deploy (no persistence layer exists yet), so there is no migration concern in practice, same
  precedent as the earlier `europe-16` → `europe-8` cut.
- Rewrite `tools/mapgen/generate-map.mjs` (currently unwired and schema-mismatched with what
  `MapRepository` actually reads) into the single, dependency-free, deterministic generator for
  *both* outputs: `Data/map.json` (schema: id, nameEn, nameRu, value, centerX/centerY, radius,
  labelX/labelY, adjacentTo) and a new client-side geometry module (SVG path `d` + centroid per
  region id), generated from the same seeded vertex data so the two never drift apart.
- Delete the real-geography rendering pipeline: `src/Triviador.Client/src/components/map/europeGeography.ts`,
  `src/Triviador.Client/scripts/generate-europe-paths.mjs`, and the `d3-geo`, `@types/d3-geo`,
  `topojson-client`, `@types/topojson-client`, `world-atlas` devDependencies they required.
- Add the replacement client-side geometry module (`abstractGeography.ts`), generated by the
  rewritten script, keyed by `RegionId`, holding an organic jigsaw-piece-shaped SVG path and a
  centroid per region.
- Update `RegionShape.tsx`/`GameMap.tsx` to import the renamed, geography-neutral geometry export
  in place of `EUROPE_GEOGRAPHY`, preserving the existing fallback-to-circle behavior for any
  region id absent from the client geometry dataset unchanged.
- Restore the region count from 8 to 18, arranged as a 6×3 grid of organic blob/jigsaw shapes
  (adapting the existing unwired `tools/mapgen/generate-map.mjs` reference implementation), with
  4-neighbour adjacency (trivially connected) and the middle row worth 400 points, outer rows worth
  200 — verified compatible with `GameRules.MinimumBaseDistance = 2` for up to 4 players (see
  design.md).
- Invent English and Russian names for all 18 regions with no real-world place references.
- **Delete** the entire in-flight, not-yet-archived `openspec/changes/realistic-europe-map-responsive-layout/`
  change folder: it documents the real-geography approach this change reverses. Its responsive
  app-shell CSS (fluid `clamp()` max-width, the 1440px breakpoint, safe-area-inset handling) was
  already implemented in `App.css` and is carried forward untouched by this change — only the
  map-rendering-specific parts of that superseded proposal are undone.
- No changes to `Triviador.Domain`, `Triviador.Application`, `Triviador.Infrastructure` logic, or
  any wire DTO — `RegionDescriptor`'s shape, `MapValidator`, and `MapRepository`'s parsing are
  already geography-agnostic and region-count-agnostic; only map *content* and the client's static
  geometry dataset change.

## Capabilities

### New Capabilities
- `map-rendering`: the client SHALL render each region as a distinct abstract shape (an organic
  jigsaw/blob-style SVG path, not a circle and not a real-world geographic outline), with all
  per-region visual states (ownership color, eligibility highlight, contested marker, base wax
  seal, adjacency lines, labels) attached to that shape. (This capability name was previously
  proposed by `realistic-europe-map-responsive-layout` for the real-geography version; that change
  is being deleted before archiving, so `map-rendering` does not yet exist under `openspec/specs/`
  — this is a fresh "New Capability", not a modification.)

### Modified Capabilities
- `map-topology`: adds an explicit region-count invariant (18) and a naming-convention requirement
  (region display names must not reference real-world places), neither of which the existing spec
  states today.
