## Why

Triviador is functionally complete through Battle (M5) but has never had a design pass: the client
is still substantially the unmodified Vite starter template (`#242424` background, `#646cff` hover
borders, `<title>Vite + React + TS</title>`, a dead `prefers-color-scheme` fork, an 18-region map
rendered as a spreadsheet-like 6×3 grid of identical squares). Feedback for in-flight game state is
plain text or, in several cases, entirely missing: `AnswerRoster`'s waiting state, the reveal
ranking/speed, connection loss/room closure, and score changes on capture have no visible treatment.
Now that the rules are stable, this is the right point to give the game a committed visual identity
before content/bot work (M6/M7) builds further on top of the current screens.

## What Changes

- Server (additive only — no rule or timing changes): map regions gain a display `Name` and label
  coordinates; base-pick eligibility is projected to the client the same way region-pick and
  attack-target eligibility already are; battle state (duel vs. base-assault, contested region,
  attacker/defender, assault progress) is projected instead of being reconstructable only from raw
  `PendingActivity` internals the client never receives; player connection state is projected.
- The placeholder map is replaced by a hand-authored organic 18-territory map, generated by a
  committed, reproducible tool, preserving the existing adjacency graph and 200/400 value split
  exactly — only geometry, names, and label positions change.
- Client gets a full design-token system (parchment/ink/gilt/heraldic-seat palette, self-hosted
  variable fonts), a persistent app shell all six screens render into (the map no longer unmounts on
  phase change), a single shared map component replacing three copy-pasted SVG blocks, a shared
  activity-component layer (question card, timer, answer roster, reveal overlay, player roster,
  odometer, connection badge, toast) replacing screen-local duplicates, and motion-driven set-pieces
  for claim/capture/assault/elimination/victory moments, computed by diffing consecutive server
  snapshots (no new event/delta channel).
- **BREAKING** (test-only): `tests/e2e/specs/room-lobby.spec.ts` currently locates elements via CSS
  classes, placeholder text, and role/name queries that this change's markup rewrite invalidates. The
  spec and its helpers are updated to use newly-added `data-testid` attributes in the same change.

## Capabilities

### New Capabilities
- `client-presentation`: the client's rendering obligations — render server-projected state only (no
  rule re-derivation), give every pending activity a visible actor/countdown/affordance, give every
  state change the player caused or suffered visible feedback, surface connection loss, honour
  reduced-motion.

### Modified Capabilities
- `map-topology`: regions gain a display name and label coordinates for rendering; adjacency and the
  200/400 value denominations are unchanged.
- `base-selection-flow`: the eligible-region set for a base pick is now projected to the client
  (today it is not, so the UI cannot highlight legal picks and relies solely on
  `BaseTooCloseToExistingBase` rejections after the fact).
- `battle-flow`: the contested region, duel-vs-base-assault distinction, and assault progress are
  projected so the client can describe what a fight is actually about.

## Impact

- Server: `Triviador.Domain/Map/RegionDescriptor.cs`, `Triviador.Domain/Engine/GameEngine.BaseSelection.cs`
  (new pure query), `Triviador.Infrastructure/Content/MapRepository.cs`,
  `Triviador.Application/Contracts/GameViewDto.cs`, `Triviador.Application/Hosting/RoomActor.cs`
  (`BuildGameView`), `src/UI/Triviador.Web/Data/map.json` (regenerated), new
  `tools/mapgen/generate-map.mjs`.
- Client: new `motion` (framer-motion) and self-hosted `@fontsource-variable/fraunces` +
  `@fontsource-variable/inter` dependencies; new `theme/`, `lib/seats.ts`, `components/` (shell, map,
  shared activity components), `hooks/useGameTransitions.ts`; every screen under `src/screens/`
  rewritten on top of the new component layer; `api/contracts.ts` hand-synced with the new DTO
  fields.
- Tests: `tests/e2e/specs/room-lobby.spec.ts` and `helpers.ts` updated to use `data-testid` selectors
  instead of today's class/placeholder/role-text queries.
- No changes to `GameRules` tunables, `AnswerRanker`, phase transitions, or timing windows.
